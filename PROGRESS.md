# PROGRESS: dependency graph of remaining work

Nodes are topologically sorted: a node may start only when every dependency is `[x]`. Each node
lists its status, dependencies, the command that verifies it, and its benchmark target. Node
status is the only place progress is recorded. `ROADMAP.md` is the user-facing narrative and
is updated in the same PR.

Status legend:
- `[ ] Not Started`
- `[~] In Progress`
- `[x] Parity Verified` (all verify commands pass on the branch)
- `[!] Blocked` (three consecutive red attempts; reason and DECISIONS.md entry required)

Verification command shorthand (defined in AGENTS.md section 13):
- `GATES`: `cargo check --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`, `maturin develop -r`, `pytest tests/parity tests/python_package_test`.
- `STAGE`: the stage golden diff (Phase C of the harness, see the plan). Until it exists, `STAGE` is
  `n/a` and the node's verify line says so.

- [x] T2.1 (PR #84, row-major copy in PR #92; column-wise stays the auto default, see DECISIONS D-006) Row-wise histogram layout for `force_row_wise` (dense single-value groups). Depends: T0.3. Forced-row training was measured in D-019: dense 1-thread beats upstream; dense 2-thread retains an upstream gap (the direct before/after control shows no regression).
- [x] T2.2 Row-wise layout auto-choice (upstream `force_col_wise`/`force_row_wise` selection rules). The layout choice is performance-only (both layouts build bit-identical histograms, so the model is the same either way, pinned by `tests/parity/test_auto_layout_parity.py`). Setting both force flags now raises like upstream's `Dataset::GetShareStates` fatal. Upstream picks the layout by timing both at runtime; bankai's column-wise is at least as fast as its dense row-wise path on every measured shape (dense `auto` 0.80x/0.64x upstream at 1/2 threads; `col` 0.69x/0.58x; `row` 0.95x/0.99x), so the auto path stays column-wise with no timing overhead rather than mirroring upstream's probe (see DECISIONS D-013, extends D-006). Depends: T2.1. Verify: `pytest tests/parity -k auto_layout`, GATES. Bench: `benches/bench_train_interleaved.py` (dense, both thread counts).
- [x] T2.3 Row-wise for multi-value groups (upstream `GetMultiBinFromAllFeatures`, all groups). Mixed groups now share one dense/sparse view with row-wise offsets and common row blocks; sparse single-value groups are accepted too. Native layout tests and 22 new parity cases pass. Seven-round Criterion ratios vs af07e1f: mixed sparse 0.9934x, mixed dense 0.9508x; all kernels within 5%. Direct Python controls show no regression in the remaining upstream-gap cases (D-019); overall speed targets remain T3.1/T3.2. Depends: T2.1. Verify: `pytest tests/parity/test_multi_val_training_parity.py -k row_wise`, GATES. Bench: `benches/bench_train_interleaved.py` (sparse).
- [x] T2.4 `spin_pool -> rayon` migration (SPEC-CONC-1, SPEC-CONC-5). `utils::spin_pool` is replaced by `utils::worker_pool::WorkerPool`, a per-Booster `rayon::ThreadPool` (never the global pool) with the same safe primitives (`run`, `for_each_mut`, `for_each_chunk_mut`, `for_each_range_mut`) but no `unsafe`. The key to meeting the gate: each tree runs inside one `pool.install`, so the per-region primitives nest on an already-active pool instead of re-entering rayon (and waking sleeping workers) each region — raising the parallel thresholds instead made it worse (see DECISIONS D-016). Interleaved medians (release, 50k rows, 50 rounds, 9 rounds, bankai/upstream ratio) vs the spin_pool baseline: dense 1-thread 0.795 vs 0.797, dense 2-thread 0.665 vs 0.656 (+1.4%), sparse 2-thread 0.907 vs 0.915; 2-thread scaling dense 1.49x, sparse 1.66x (both well above the 1.2x floor). `thread_invariance` passes for 1, 2 and 3 threads. Depends: T1.5, T2.1. Verify: `cargo test -p lgbm-core --test thread_invariance` for 1, 2 and 3 threads, GATES. Bench: interleaved kernels and `benches/bench_train_interleaved.py` at 2 threads; no slowdown above 3% against the spin_pool baseline.
- [x] T2.5 Histogram pool and subtraction trick (`histogram_pool_size`). Positive MB budgets use upstream-sized LRU buckets (minimum two); hits/moves refresh recency, evicted parents rebuild, and the existing subtraction path handles cached parents. Budget-only resets preserve capacity and sampling streams; num_leaves changes recalculate capacity. Four native tests and 36 parity cases pass; all Criterion kernels remain within 5% of main (D-020). Depends: T2.1. Verify: `pytest tests/parity -k histogram_pool`, GATES. Bench: `benches/bench_train_interleaved.py`.
- [x] T2.6 SIMD histogram kernels with scalar fallback, bit-exact to the scalar path (SPEC-CONC-6). Dense updates pair gradient/Hessian lanes; the common numerical scan pairs left/right gains (runtime NEON/SSE2, unchanged prefix-sum and tie order). Seven-round Criterion medians: split search 0.9474x base; all kernels within the 5% gate (D-018). Depends: T2.1. Verify: `cargo test -p lgbm-core simd`, miri for the histogram module and `cargo +nightly miri test -p lgbm-core --test simd_split_gain`. Bench: criterion kernels, no regression.
- [x] T2.7 Quantized training (`use_quantized_grad`, `num_grad_quant_bins`). Nearest-rounding foundation added: packed int8 row derivatives, f64 scales, reusable buffers and 8/16/32-bit width selection. Six native tests include statistics from 16 upstream stumps (D-021/D-022). The `std::mt19937` engine that stochastic rounding seeds is ported and pinned to the C++ standard's conformance vector (D-023). The packed integer gradient/Hessian histogram construction (8/16/32-bit widths, upstream's single-add packing) is ported and verified against brute-force per-bin sums (D-024). The integer numerical split search (`FindBestThresholdSequentiallyInt`/`BeforeNumericalInt`: exact integer prefix sums scaled once, row counts from `cnt_factor`, kEpsilon only in the child gain) is ported and verified against an independent brute-force reference (D-025). The serial learner now trains `use_quantized_grad` end-to-end for the deterministic nearest-rounding slice (numeric, dense column-wise, 1 thread, `stochastic_rounding=false`, `quant_train_renew_leaf=false`): integer histograms per leaf, componentwise sibling subtraction, integer split search, leaf outputs from integer sums × scales; tree-by-tree parity with `lightgbm==4.7.0` for L2 regression at `num_grad_quant_bins` 4/8/16 (D-026), and for the variable-Hessian `binary` objective (`cnt_factor != 1`). Leaf renewal (`quant_train_renew_leaf`) is implemented (D-027): leaf outputs are recomputed from the full-precision gradients after the tree is grown, parity-checked for regression and binary. Categorical features train on the integer categorical split (one-hot and many-vs-many, D-028), parity-checked at bins 4/8/16. The quantized model text is independent of `num_threads` (SPEC-NUM-3), pinned by `thread_invariance.rs` for 1/2/3 threads on dense data. Sparse data (columns bundled into a column-wise multi-value group) builds its integer histogram per-row and matches upstream (D-029). The row-wise layout (`force_row_wise`, dense and sparse) is supported via the layout-independence of the integer sums (D-030). Stochastic rounding (`stochastic_rounding=true`, the default) is implemented by porting libc++'s `uniform_real`/`uniform_int` over the mt19937 engine: the distributions are implementation-defined, so bankai pins libc++ (the host/fixture stdlib) and is bit-exact only there — the parity test runs on macOS and is skipped on Linux/Windows CI (D-031). Only an out-of-range `num_grad_quant_bins` now falls back to full precision. All CPU layouts, objectives and rounding modes of quantized training match `lightgbm==4.7.0` tree-by-tree (stochastic on libc++); CUDA/distributed quantized paths are out of scope (ROADMAP P2). Depends: T2.1, T1.2. Verify: `pytest tests/parity -k quantized`, GATES. Bench: `benches/bench_train_interleaved.py`.
